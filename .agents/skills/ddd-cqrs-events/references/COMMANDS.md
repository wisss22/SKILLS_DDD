# Commands + CommandHandlers

Los Commands representan una **intención de cambiar el estado** en el sistema. Son DTOs simples despachados a través de un CommandBus hacia un único CommandHandler que ejecuta la lógica de negocio.

## Reglas Fundamentales

### 1. Los Commands son DTOs (Sin Comportamiento)

```pseudocode
class CreateCourseCommand:
    property id: string          // Generated by caller (idempotency)
    property name: string
    property duration: int

    // Simple constructor. No validation beyond types.
    constructor(id, name, duration):
        self.id = id
        self.name = name
        self.duration = duration
```

### 2. Nombrado Imperativo

Los Commands describen QUÉ hacer. Usa verbos imperativos.

| MAL | BIEN |
|---|---|
| `CourseCreationRequest` | `CreateCourseCommand` |
| `UpdateUserData` | `UpdateUserCommand` |
| `OrderCancellation` | `CancelOrderCommand` |

### 3. Los Commands Devuelven Void

```pseudocode
class CommandBus:
    method dispatch(command: Command): void  // ← void

class CommandHandler:
    method invoke(command: Command): void    // ← void
```

Si quien llama necesita datos después del command, emite una query separada.

### 4. Un Handler por Command

```pseudocode
// Exactly ONE handler per command
class CreateCourseCommandHandler:
    property repository: CourseRepository
    property eventBus: EventBus

    method invoke(command: CreateCourseCommand): void
        course = Course.create(
            CourseId.fromValue(command.id),
            CourseName.fromValue(command.name),
            CourseDuration.fromValue(command.duration)
        )
        self.repository.save(course)
        self.eventBus.publish(course.pullEvents())
```

### 5. Handlers Delgados

Un handler debe seguir este patrón:

```pseudocode
class SomeCommandHandler:
    method invoke(command): void
        // 1. VALIDATE input (syntax/format — business rules go in domain)
        ensureValidInput(command)

        // 2. LOAD aggregate (if modifying existing)
        aggregate = self.repository.findById(command.aggregateId)
        if aggregate is null:
            throw AggregateNotFoundError

        // 3. CALL domain method (ONE line — the business logic is in the domain)
        aggregate.doSomething(command.data)

        // 4. SAVE
        self.repository.save(aggregate)

        // 5. PUBLISH events
        self.eventBus.publish(aggregate.pullEvents())
```

### 6. El Handler Depende de Puertos, No de Adaptadores

```pseudocode
// CORRECT: Depends on interfaces (ports)
class CreateCourseCommandHandler:
    constructor(
        repository: CourseRepository,   // ← PORT (interface)
        eventBus: EventBus              // ← PORT (interface)
    )

// WRONG: Depends on implementations (adapters)
class CreateCourseCommandHandler:
    constructor(
        repository: PostgresCourseRepository,  // ← Adapter (concrete)
        eventBus: RabbitMqEventBus             // ← Adapter (concrete)
    )
```

### 7. Idempotencia mediante Command ID

Los Commands llevan un ID generado por quien llama. Esto permite idempotencia: si un command se recibe dos veces (reintento de red), la segunda ejecución puede detectarse y omitirse.

```pseudocode
class CreateCourseCommand:
    property commandId: string  // UUID from the client

// In the handler:
method invoke(command):
    if self.alreadyProcessed(command.commandId):
        return  // Idempotent — do nothing
    // ... process the command
```

## CommandBus — Desacoplando el Despacho de la Ejecución

El CommandBus enruta los commands hacia sus handlers:

```pseudocode
interface CommandBus:
    method dispatch(command: Command): void

// Infrastructure adapter
class InMemoryCommandBus implements CommandBus:
    property handlers: map[CommandType, CommandHandler]

    method register(commandType, handler):
        self.handlers[commandType] = handler

    method dispatch(command):
        handler = self.handlers[typeOf(command)]
        if handler is null:
            throw CommandNotRegisteredError
        handler.invoke(command)
```

## Errores Comunes

1. **Commands que devuelven datos**: `dispatch(command): Response` — usa una Query en su lugar
2. **Lógica de negocio en handlers**: Más de ~5 líneas de lógica de dominio
3. **Handler llamando a múltiples aggregates**: Una transacción, un aggregate
4. **Commands con comportamiento**: Validación o reglas de negocio en el Command DTO
5. **Handler dependiendo de adaptadores concretos**: Depende de interfaces (puertos)
6. **Sin command ID**: No se puede implementar idempotencia
